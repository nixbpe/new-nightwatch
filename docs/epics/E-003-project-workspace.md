# E-003 ภาพรวมและการตรวจสถานะบริการภายใต้ Project

| Field          | Value                                    |
| -------------- | ---------------------------------------- |
| Direction      | `DIR-001 / v4`, `docs/product-direction.md` |
| Status         | Draft                                    |
| outcome_status | Not measured                             |
| Owner          | Product Owner role; ยังไม่ยืนยันผู้รับผิดชอบรายบุคคล |

## Outcome

สมาชิก Project เห็นสถานะบริการและเหตุการณ์ของ Project ที่ตนดูแลในที่เดียว และจัดการมอนิเตอร์เฉพาะของ Project นั้น โดยไม่เห็นมอนิเตอร์ของ Project อื่น

## ขอบเขตและกฎสำคัญ

- มอนิเตอร์ทุกตัวสังกัด Project เดียว และ Project สังกัด Organization เดียว
- หน้าภาพรวมและหน้าตรวจสถานะบริการแสดงเฉพาะข้อมูลของ Project ที่เลือก
- ผู้ที่เห็นมอนิเตอร์ได้คือผู้ที่เข้าถึง Project นั้นได้ตาม `E-001`
- การตรวจสถานะบริการยังเป็นความสามารถสนับสนุนตาม `DIR-001` S2
- ไม่ย้ายข้อมูลมอนิเตอร์เดิม ข้อมูลมอนิเตอร์ที่มีอยู่ถูกล้างเมื่อเปลี่ยนเป็นโครงสร้างใหม่ (คำตอบของผู้ใช้ 2026-10-11)

## Features

| Feature | Summary | Status |
| ------- | ------- | ------ |
| `F-011` | มอนิเตอร์ เหตุการณ์ และการแจ้งเตือนอยู่ภายใต้ Project | Candidate / Draft |
| `F-012` | หน้าภาพรวมของ Project | Candidate / Draft |

## Out of scope

- ภาพรวมรวมทุก Project ระดับ Organization (ข้อเสนอ ยังเป็นคำถามที่เปิดอยู่จากรอบออกแบบ)
- การย้ายมอนิเตอร์ข้าม Project
- การย้ายข้อมูลมอนิเตอร์เดิมเข้า Project

## Risks and dependencies

- `R-01`: การล้างข้อมูลมอนิเตอร์เป็นการลบถาวร ถ้ามี environment ที่มีข้อมูลจริงต้องยืนยันก่อน deploy
- `R-02`: ผู้รับการแจ้งเตือนของมอนิเตอร์เปลี่ยนจากระดับ Organization เป็นระดับ Project ต้องกำหนดใน `F-011`
- ต้องมี `F-001` และ `F-002` ก่อน เพราะมอนิเตอร์ต้องมี Project และสิทธิ์ Project
