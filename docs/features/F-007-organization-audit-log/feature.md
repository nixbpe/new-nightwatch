## Problem and scope

`owner` และ `admin` ของ Organization ต้องตอบคำถาม "ใครทำอะไร กับอะไร เมื่อไร" ใน Organization ของตน เช่น ใครเปลี่ยน role ใครถอนสมาชิก ใครหยุดหรือลบมอนิเตอร์ ใครแทนที่ค่าลับ ใครปิด "แจ้งเตือนมอนิเตอร์" ตอนนี้ไม่มีหน้าจอให้ตอบ ระบบเขียนเพียง Pino log แบบ best-effort ที่ผู้ใช้ปลายทางเข้าไม่ถึง (`apps/api/src/monitors/audit.ts`) และ action ของสมาชิกกับคำเชิญบันทึกเฉพาะ denial (`apps/api/src/organization-notifications/routes.ts`, `F-006` `OD-17`)

- In scope:
  - หน้ารายการกิจกรรมที่สำเร็จของ Organization ที่เลือก หน้าละ 50 แถว ใหม่สุดก่อน
  - ตัวกรองช่วงเวลา หมวด ผู้ดำเนินการ และการค้นหาข้อความ
  - หน้ารายละเอียดของเหตุการณ์ พร้อมการเปลี่ยนแปลงก่อน/หลังที่ไม่มีข้อมูลส่วนบุคคลและค่าลับ
  - ส่งออก CSV และ JSON แบบ async พร้อมแจ้งเตือนใน inbox เมื่อไฟล์เสร็จหรือล้มเหลว (เฉพาะ `owner`/`admin`) ผู้ใช้มีคำขอที่กำลังสร้างได้ครั้งละ 1 คำขอต่อ Organization
  - `auditor` อ่านรายการและรายละเอียดได้ รวมชื่อผู้ดำเนินการและชื่อสมาชิกที่เป็นเป้าหมาย ส่งออกไม่ได้
  - บันทึก event แบบ in-transaction: ถ้าบันทึกไม่สำเร็จ mutation ล้มเหลวด้วย
  - เก็บ event 365 วัน
  - บันทึกการส่งออกเป็น event ในหมวด "บันทึกกิจกรรม"
  - สถานะ loading, empty, error, denied ของทุกหน้าจอ
- Non-goals:
  - event ที่ถูกปฏิเสธ (denial) และตัวกรองผลลัพธ์ (`OD-03`)
  - ข้อมูลส่วนบุคคลใน event: IP, user agent, อีเมลของผู้ดำเนินการและของผู้รับคำเชิญ (`OD-02`)
  - event ระดับบัญชี: sign-in, รหัสผ่าน, MFA, session (`OD-09`)
  - การบันทึกการเปิดดูบันทึกกิจกรรม (`OD-15`)
  - หมวดที่ระบบยังไม่มี: AWS account, API key ของ Organization, findings, policy, การเปลี่ยนชื่อหรือลบ Organization
  - การแก้ไขหรือลบ event โดยผู้ใช้ การดูข้าม Organization และ platform-admin view
  - รายงาน compliance, SIEM/webhook streaming, การแจ้งเตือนจาก event
  - การเปรียบเทียบหลายเหตุการณ์พร้อมกัน
  - การตอบรับคำเชิญ (สมาชิกเข้าร่วม), operator provisioning และ demo seed (`P-05`)

ค่าทำงานที่ผู้ใช้อนุมัติพร้อม Technical Spec (2026-10-03): ส่งออกได้ไม่เกิน 50,000 event และ 25 MiB ต่อไฟล์ ไฟล์เก็บใน PostgreSQL และดาวน์โหลดได้ 24 ชั่วโมงหลังสร้างเสร็จ section `ไฟล์ส่งออกของฉัน` แสดงคำขอ 7 วันล่าสุด ไม่เกิน 20 แถว (`P-06`) คำขอที่ค้างเกิน 60 นาทีเป็น "ล้มเหลว" ไม่มี quality target

Organization เป็น tenant boundary server ตรวจ session, membership และ permission ของทุก operation ค่า Organization จาก URL หรือ browser ไม่ให้สิทธิ์ event ของ Organization A ต้องไม่ปรากฏใน Organization B

## Outcome

`E-002` Outcome ยังไม่ครอบคลุมบันทึกกิจกรรม (ยังไม่ได้รับคำสั่งให้แก้ Outcome ของ `E-002`) ข้อเสนอสำหรับ Outcome ของ `E-002`: `owner`/`admin` หาได้เองว่าใครทำการเปลี่ยนแปลงใดใน Organization ภายในระยะเก็บ โดยไม่เข้าใจผิดว่าหมวดที่ยังไม่บันทึกไม่มีกิจกรรม

| Metric (ข้อเสนอ) | นิยาม | ประชากร / ช่วงเวลา | แหล่งข้อมูล | Baseline |
| ---------------- | ----- | ------------------ | ----------- | -------- |
| M-A ความสำเร็จของงานค้นหา | งาน "หาว่าใครทำ X ในช่วง Y" ที่ตอบถูก หารด้วยงานที่พยายามทั้งหมด รวมงานที่เลิกกลางทาง | `owner`/`admin` ใน pilot ช่วงศึกษาที่ตกลงก่อน | usability study (ยังไม่มี protocol) | ไม่ทราบ เสนอวัดรอบแรก |

## UI flow

ร่างร่วมกับ agent:`ux-designer` เมื่อ 2026-10-02 ก่อนคำตัดสิน `OD-02` ถึง `OD-15` Product Owner ปรับตามคำตัดสินแล้ว UX Designer review flow การส่งออกและมุมมองของ `auditor` เมื่อ 2026-10-03 (ผลส่งผ่าน coordinator) Product Owner ปิด finding `B-1`, `B-2`, `M-1`–`M-10`, `a-1`, `a-2` และ `m-5` ในหัวข้อนี้ ยังไม่ตรวจ runtime

กติการ่วม: ทุกตัวควบคุมที่ "ใช้ไม่ได้พร้อมเหตุผล" ใช้ `aria-disabled` + `aria-describedby` ชี้ไปที่ข้อความเหตุผลที่มองเห็นได้ ไม่ใช้ `disabled` (`M-2`)

ที่ตั้ง:

- route รายการ `/organizations/:organizationId/audit-log` และรายละเอียด `/organizations/:organizationId/audit-log/:eventId`
- nav leaf `บันทึกกิจกรรม` ใน group `องค์กร` ต่อจาก `ตั้งค่าการแจ้งเตือน` และตั้ง `roles: ["owner","admin","auditor"]` ตามแบบใน `apps/web/src/components/shell/nav-config.ts` icon ใหม่ `history` ใน `NAV_ICONS` (`OD-12`)
- เฟรมตาม `docs/ref/shell-structure.md`: eyebrow `// audit-log`, scope row, title `บันทึกกิจกรรมองค์กร`, status line, section header

ขั้นตอน:

1. `owner`, `admin` หรือ `auditor` เปิดหน้าจาก sidebar หรือ ⌘K หน้าแสดง status line `ทั้งหมด N รายการ · เก็บย้อนหลังถึง <วันที่> · เวลาแสดงตาม <timeZone> · โหลดเมื่อ HH:MM:SS` และ note ขอบเขตการบันทึก ค่าเริ่มต้นคือ 7 วันล่าสุด ใหม่สุดก่อน หน้าละ 50 แถว ไม่มี auto-refresh มีปุ่ม `รีเฟรช` `auditor` ไม่เห็นปุ่ม `ส่งออก` และไม่เห็น section ไฟล์ส่งออก
2. "เก็บย้อนหลังถึง" คือวันที่ที่ใหม่กว่าระหว่าง 365 วันก่อนวันนี้ กับวันที่เริ่มบันทึกของ Organization
3. Note ขอบเขตการบันทึก แสดงถาวรในหน้ารายการและ export dialog: "บันทึกเฉพาะการกระทำที่สำเร็จในหมวด มอนิเตอร์ ตั้งค่าการแจ้งเตือน สมาชิก คำเชิญ และบันทึกกิจกรรม ตั้งแต่ <วันที่เริ่มบันทึก> ไม่รวมการกระทำที่ถูกปฏิเสธ การตอบรับคำเชิญ (สมาชิกเข้าร่วม) กิจกรรมระดับบัญชี (เข้าสู่ระบบ รหัสผ่าน MFA) และกิจกรรมของ AWS account, API key และ findings" (`P-05`)
4. ผู้ใช้กรองด้วย chip ขนาด 32 px: ช่วงเวลา (24 ชั่วโมง / 7 วัน / 30 วัน / กำหนดเอง), หมวด (เลือกได้หลายค่า), ผู้ดำเนินการ (combobox) และค้นหาด้วยช่อง `ค้นหา` ที่ทำงานเมื่อกด Enter หรือกดปุ่ม ทุกการเปลี่ยนกลับไปหน้า 1 เขียนค่าลง query string และแทนแถวเก่าด้วย skeleton จากนั้น live region ประกาศ `พบ N รายการ` มีแถบสรุปตัวกรองและปุ่ม `ล้างตัวกรอง`
5. ช่วงกำหนดเองที่วันเริ่มอยู่หลังวันสิ้นสุด หรือเก่ากว่าวันที่ "เก็บย้อนหลังถึง" แสดง error ข้างช่อง คงค่าไว้ และไม่ส่ง request
6. ผู้ใช้กดลิงก์ในเซลล์ `เวลา` เพื่อเปิดหน้ารายละเอียด focus ไปที่ h1 ลิงก์ `กลับไปบันทึกกิจกรรม` คืน query string เดิม และคืน focus ไปที่ลิงก์ของแถวนั้น หน้ารายละเอียดของ `organization.audit-log.export` แสดง section "ขอบเขตการส่งออก" แทน "การเปลี่ยนแปลง": รูปแบบ, ช่วงวันเวลา `from`–`to` พร้อม zone, หมวด, ผู้ดำเนินการ และ "มีการค้นหาข้อความ: ใช่/ไม่" โดยไม่แสดงคำค้น (`a-2`)
7. `owner`/`admin` กด `ส่งออก` modal `ส่งออกบันทึกกิจกรรม` เปิด เนื้อหา dialog:
   - ขอบเขตใช้ `asOf` และช่วงวันที่ `from`/`to` เดียวกับรายการที่แสดงอยู่ พร้อมบรรทัด "ณ โหลดเมื่อ HH:MM:SS (<timeZone>)" ช่วงวันที่แสดงเป็นวันเวลาจริงพร้อม zone ตัวกรองที่ใช้ และจำนวนรายการ (`M-4`)
   - ตัวเลือก CSV/JSON อยู่ใน `fieldset` ที่มี `legend` "รูปแบบไฟล์" ค่าเริ่มต้น CSV (`M-3`)
   - note ขอบเขตการบันทึก
   - ปุ่ม `สร้างไฟล์` และ `ยกเลิก`
   - ผลลัพธ์ 0 รายการ: ปุ่ม `ส่งออก` บนหน้า (`aria-disabled`) มีเหตุผล "ไม่มีรายการให้ส่งออกตามตัวกรองนี้"
   - ผลลัพธ์เกิน 50,000 รายการ: dialog แสดง "ข้อมูลมากเกินไปสำหรับการส่งออกครั้งเดียว ลดช่วงเวลาแล้วลองใหม่ (พบ <N> รายการ สูงสุด 50,000)" และปุ่ม `สร้างไฟล์` เป็น `aria-disabled` ชี้ไปที่ข้อความนี้ (`P-01`)
   - เมื่อเนื้อหาสูงกว่า viewport เนื้อหาเลื่อนในตัว dialog โดย title และแถวปุ่มยังมองเห็น (`M-3`)
8. ผู้ใช้กด `สร้างไฟล์` ระหว่างส่ง ปุ่มแสดง "กำลังส่งคำขอ…" (`aria-busy`) `ยกเลิก` และ Escape ไม่ทำงาน (`aria-disabled`) จนได้ผล (`M-3`)
   - POST ได้ `422` เพราะเกิน 50,000: dialog เปลี่ยนเป็น state เกินขนาดพร้อมจำนวนล่าสุดจาก response (`M-4`)
   - POST ได้ `422` เพราะไม่มีรายการ: "ไม่มีรายการให้ส่งออกตามตัวกรองนี้" ใน dialog
   - POST ได้ `409` (มีคำขอกำลังสร้างอยู่): ปิด dialog โหลดรายการไฟล์ส่งออกใหม่ และปุ่มแสดงสถานะตามขั้นตอน 9
   - network หรือ error อื่น: "ส่งคำขอส่งออกไม่สำเร็จ ตัวเลือกของคุณยังอยู่ ลองใหม่อีกครั้ง" ใน dialog
   - `201`: server บันทึกคำขอเป็น event ในหมวด "บันทึกกิจกรรม" dialog ปิดหลังได้ `201` เท่านั้น ก่อนได้ผลจาก server dialog ยังเปิดอยู่ในสถานะส่งคำขอ (`m-6`) focus กลับไปปุ่มส่งออก notice ใต้ page header แสดงประโยคเต็ม "กำลังสร้างไฟล์ เราจะแจ้งใน การแจ้งเตือน เมื่อพร้อมดาวน์โหลด" โดยคำว่า `การแจ้งเตือน` เป็นลิงก์ไป `/notifications` พร้อมลิงก์ `ดูไฟล์ส่งออกของฉัน` ที่ย้าย focus ไปที่ h2 ของ section (`M-5`) notice ไม่ปิดเอง มีปุ่ม `ปิด` (ชื่อ "ปิดข้อความ") และหายเมื่อออกจากหน้า เมื่อปิด focus ไปที่ปุ่มส่งออก (`m-1`) ปุ่มส่งออกใช้ label สั้น `กำลังสร้างไฟล์…` section `ไฟล์ส่งออกของฉัน` แสดงแถวใหม่สถานะ "กำลังสร้าง"
9. ทันทีที่ได้ `201` ก่อน refetch (`M-1`) และตลอดเวลาที่คำขอของผู้ใช้ใน Organization นี้กำลังสร้าง (`OD-18`):
   - ปุ่มส่งออกเปลี่ยน label เป็น `กำลังสร้างไฟล์…` เป็น `aria-disabled` เหตุผล "สร้างไฟล์ส่งออกได้ครั้งละ 1 คำขอ รอให้ไฟล์ปัจจุบันเสร็จก่อน คำขอที่ยังไม่เสร็จภายใน 60 นาทีจะถือว่าล้มเหลว" (`m-4`) และเปิด dialog ไม่ได้
   - ปุ่ม `ขอใหม่` ทุกแถวเป็น `aria-disabled` ด้วยเหตุผลเดียวกัน
   - เมื่อคำขอเสร็จหรือล้มเหลว ปุ่มกลับเป็น `ส่งออก`
10. Section `ไฟล์ส่งออกของฉัน` (h2 รับ focus ได้ด้วย `tabindex="-1"`):
    - ใช้ `<table>` ที่มี caption คอลัมน์ รูปแบบ, ขอบเขต, ขอเมื่อ, สถานะ, การดำเนินการ (`M-8`)
    - ขอบเขตของแถวแสดงขอบเขตจริงของคำขอ: ช่วงวันเวลา `from`–`to` พร้อม zone, หมวด, ผู้ดำเนินการ และ "มีการค้นหาข้อความ" ถ้ามี (ไม่แสดงคำค้น) (`B-1`)
    - เวลา "ขอเมื่อ" และ "ดาวน์โหลดได้ถึง" ใช้ `formatAuditTimestamp` (วันที่ เวลา และชื่อ zone) แบบเดียวกับตารางรายการ (`m-3`)
    - เมื่อมีคำขอใน 7 วันเกิน 20 รายการ ใต้ตารางแสดง "แสดง 20 รายการล่าสุด" (`m-4`, CMP-01)
    - live region เดียวของ section (`role="status"`) ประกาศเฉพาะการเปลี่ยนสถานะ เช่น "ไฟล์ CSV ที่ขอเมื่อ 2026-10-03 14:05:10 Asia/Bangkok พร้อมดาวน์โหลด" ไม่ประกาศแถวทั้งหมดซ้ำเมื่อ poll (`M-8`)
    - ชื่อปุ่มของแต่ละแถวระบุรูปแบบและเวลาขอ เช่น "ดาวน์โหลด CSV ที่ขอเมื่อ 2026-10-03 14:05" และ "ขอใหม่ CSV ที่ขอเมื่อ 2026-10-03 14:05" (`M-8`)
    - poll ล้มเหลว: คงแถวเดิม แสดง "ข้อมูลอาจไม่เป็นปัจจุบัน" + `ลองใหม่` ที่หัว section ไม่ล้างแถว (`M-8`)
    - ระหว่างโหลดครั้งแรก skeleton มีความสูงขั้นต่ำเท่าหัว section กับหนึ่งแถว เพื่อลด layout shift ถ้าไม่มีคำขอ section ซ่อนตามเดิม (`m-5`)
11. สถานะของแถว:
    - "กำลังสร้าง": ไม่มีปุ่ม
    - "พร้อมดาวน์โหลด": "ดาวน์โหลดได้ถึง <วันเวลา zone>" และปุ่ม `ดาวน์โหลด` ระหว่างดาวน์โหลด ปุ่มแสดง `กำลังดาวน์โหลด…` เป็น `aria-disabled` (`M-7`)
    - "ล้มเหลว": บรรทัดเหตุผลหนึ่งบรรทัดตาม `failureCode` (`M-6`) และปุ่ม `ขอใหม่`
      - `EXPORT_TOO_LARGE`: "ไฟล์ใหญ่เกิน 25 MiB ขอใหม่ด้วยขอบเขตเดิมจะล้มเหลวอีก ลดช่วงเวลาหรือเพิ่มตัวกรองก่อน" พร้อมลิงก์ `ปรับตัวกรอง` ที่ใส่ขอบเขตของแถวลงตัวกรองของรายการและย้าย focus ไปที่ section ตัวกรอง ใต้ลิงก์มีบรรทัดอธิบาย "ตัวกรองใช้ช่วงเต็มวัน จึงอาจกว้างกว่าช่วงของไฟล์นี้" เพราะช่วงกำหนดเองของตัวกรองเป็นระดับวัน (UX `N-3`)
      - `EXPORT_FAILED` และรหัสอื่น (รวมคำขอที่ค้างเกิน 60 นาที): "สร้างไฟล์ไม่สำเร็จเพราะระบบขัดข้อง ขอใหม่ได้ด้วยขอบเขตเดิม"
      - `REQUESTER_NOT_AUTHORIZED`: "สร้างไฟล์ไม่สำเร็จเพราะสิทธิ์ส่งออกของคุณเปลี่ยนระหว่างสร้าง"
    - "หมดอายุ" (24 ชั่วโมงหลังสร้างเสร็จ): "ไฟล์หมดอายุแล้ว" และปุ่ม `ขอใหม่` (`M-9`)
12. `ขอใหม่` (`B-1`, `M-9`) ส่งคำขอใหม่ด้วยรูปแบบและขอบเขตเดิมของแถว: ช่วงวันเวลา `from`/`to` แบบ absolute ตัวเดิม หมวด ผู้ดำเนินการ และคำค้นเดิม ไม่ใช่ช่วงสัมพัทธ์ เช่น "7 วัน" ถ้า `from` เก่ากว่าระยะเก็บแล้ว ผลของ server เป็นตัวตัดสิน ไม่เปิด dialog
    - สำเร็จ (`201`): เหมือนขั้นตอน 8 และ 9 แถวใหม่สถานะ "กำลังสร้าง" ขึ้นบนสุด
    - ล้มเหลว: error แสดงในแถวนั้นด้วย `role="alert"` และปุ่ม `ขอใหม่` ชี้ไปที่ข้อความด้วย `aria-describedby` ข้อความเดียวกับ dialog: `422` เกินขนาด "ข้อมูลมากเกินไปสำหรับการส่งออกครั้งเดียว ลดช่วงเวลาแล้วลองใหม่ (พบ <N> รายการ สูงสุด 50,000)", `422` ไม่มีรายการ "ไม่มีรายการให้ส่งออกตามตัวกรองนี้", `409` "สร้างไฟล์ส่งออกได้ครั้งละ 1 คำขอ รอให้ไฟล์ปัจจุบันเสร็จก่อน", network หรืออื่น ๆ "ส่งคำขอส่งออกไม่สำเร็จ ลองใหม่อีกครั้ง"
13. `ดาวน์โหลด` ล้มเหลว (`M-7`): error แสดงในแถวด้วย `role="alert"`
    - `404`: "ไม่พบไฟล์นี้ โหลดรายการล่าสุดแล้ว" และ refetch
    - `409`: "ไฟล์ยังไม่พร้อม โหลดรายการล่าสุดแล้ว" และ refetch
    - `410`: แถวเปลี่ยนเป็น "หมดอายุ" พร้อม "ไฟล์หมดอายุแล้ว" และ `ขอใหม่`
    - network: "ดาวน์โหลดไม่สำเร็จ ลองใหม่อีกครั้ง"
    - `403`: ตามขั้นตอน 15
14. เมื่อไฟล์เสร็จหรือล้มเหลว ผู้ขอได้ notification ใน inbox หมวด "องค์กร / บันทึกกิจกรรม" พร้อมลิงก์ `เปิดบันทึกกิจกรรม` ที่ไปที่ section `ไฟล์ส่งออกของฉัน` ของหน้าบันทึกกิจกรรม (anchor) และ focus ที่ h2 ของ section ถ้า section ไม่แสดงแล้ว (เช่นผู้ขอเป็น `auditor`) หน้าเปิดที่ด้านบนตามปกติ (`M-10`) ข้อความ notification: "ไฟล์ส่งออกบันทึกกิจกรรมพร้อมดาวน์โหลด" และ "สร้างไฟล์ส่งออกไม่สำเร็จ" กฎของ notification: ไฟล์ที่เกิน 25 MiB ระหว่างสร้างเป็น "ล้มเหลว" (`P-01`) คำขอที่ค้างเกิน 60 นาทีเป็น "ล้มเหลว" และผู้ขอได้ notification แม้ไม่กลับมาที่หน้า (`P-08`) ถ้าผู้ขอไม่ได้เป็น `owner`/`admin` แล้วตอนคำขอล้มเหลว ผู้ขอยังได้ `AUDIT_EXPORT_FAILED` เมื่อยังเป็นสมาชิก และไม่ได้เมื่อถูกถอนแล้ว (`P-07`) ไฟล์ดาวน์โหลดได้ 24 ชั่วโมงหลังสร้างเสร็จ จากนั้นแถวเป็น "หมดอายุ" (`P-06`)
15. Role ถูกลดหรือถูกถอนขณะเปิดหน้า:
    - เป็น `viewer` หรือถูกถอน: request ถัดไปได้ denied หน้าล้างแถวและจำนวน แล้วแสดงการ์ด denied และ focus ไปที่หัวข้อการ์ด
    - จาก `owner`/`admin` เป็น `auditor` (`B-2`): `403` จากรายการไฟล์ส่งออก (รวม poll) การส่งออก `ขอใหม่` หรือดาวน์โหลด ใช้กติกาเดียวกันทุกทาง: หยุด poll, โหลด context ใหม่, ซ่อนปุ่ม `ส่งออก` และ section `ไฟล์ส่งออกของฉัน` แล้วแสดง notice ระดับหน้าเหนือตาราง (`role="status"`, รับ focus ได้ด้วย `tabindex="-1"`) "สิทธิ์ส่งออกของคุณเปลี่ยนแล้ว คุณยังดูบันทึกกิจกรรมได้ แต่ส่งออกและดาวน์โหลดไฟล์ไม่ได้" และย้าย focus ไปที่ notice รายการยังอ่านได้
    - ถ้า dialog export เปิดอยู่ ให้ปิดก่อนแสดงผล
16. สลับ Organization: ยกเลิก request ของ Organization เดิม ถ้า role ใหม่เป็น `owner`, `admin` หรือ `auditor` ไปที่บันทึกกิจกรรมของ Organization ใหม่และล้างตัวกรอง ถ้าไม่ใช่ ไปที่ `/workspace` (`OD-14`) หน้ารายละเอียดกลับไปที่รายการของ Organization ใหม่
